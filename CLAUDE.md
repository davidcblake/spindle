# CLAUDE.md — Spindle

Spindle (named for the spindle of the Liahona) is a scripture study companion PWA for members of The Church of Jesus Christ of Latter-day Saints. Tap-based passage selection → a personalized, Christ-centered ten-section study generated by the Anthropic API → auto-saved to a cross-device study journal that works offline. See `docs/spindle-prd.md` for full product context. This file is your build guide.

## Non-negotiable product rules (enforce in code, not just prompts)

1. **This app exists to build faith.** It is designed for faithful members, to strengthen testimony of Jesus Christ and His restored gospel. Never surface controversy, criticism, historical debates, or critical scholarship — not even to refute it. The system prompt in `src/lib/server/prompt.ts` enforces this; never weaken that section, and any new AI feature must carry the same guardrail.
2. **The Anthropic API key never reaches the client.** All model calls go through `/api/study` (or future server routes). Verify no `ANTHROPIC` string appears in client bundles before shipping.
3. **No free text from the client ever reaches the prompt.** The client sends a structured selection (`volumeId/book/chapters/extras`); the server rebuilds and validates the reference via `validateSelection()`. Profile fields are whitespace-collapsed and length-capped in `describeReader()`. Keep both properties when extending.
4. **Every table gets owner-only RLS.** The app uses the anon key + session JWT exclusively — RLS *is* the authorization layer. No service-role key in the app runtime.
5. **A generated study is persisted before it is returned** (PRD GEN-6). Don't reorder that.
6. **Journal entries are immutable** — insert and delete only, no update policy.

## Stack

- **Next.js 16 (App Router, TypeScript)** on **Vercel**, plain CSS design tokens in `globals.css` (no Tailwind — the design system is ported from the validated prototype)
- **Supabase**: Auth (Google OAuth + email magic link, open sign-up, no passwords) + Postgres (profiles, journal_entries). Clients in `src/lib/supabase/`; session refresh in `src/middleware.ts`; schema in `supabase/migrations/`
- **AI:** Anthropic API via `@anthropic-ai/sdk`. Model from `ANTHROPIC_MODEL` (default `claude-sonnet-5`). Structured outputs via `client.messages.parse()` + `zodOutputFormat(StudySchema)`; one retry on validation failure; specific human-readable errors (never a bare "something went wrong")
- **Offline/PWA:** IndexedDB journal cache (`src/lib/journalCache.ts`, via `idb`), offline-delete queue replayed on reconnect, `public/sw.js` app-shell service worker, `public/manifest.webmanifest`
- **Icons:** generated by `node scripts/make-icons.mjs` (pure-JS PNG encoder — no native deps)

## Layout

```
src/lib/scripture.ts        VOLUMES data + mergeRanges/buildReference/validateSelection (shared client+server)
src/lib/study.ts            StudySchema (zod) + JournalEntry + fallback parser
src/lib/server/prompt.ts    system prompt + profile personalization (server-only)
src/lib/journalCache.ts     IndexedDB cache + pending-delete queue
src/app/api/study/route.ts  auth → validate → rate limit → generate → persist → return
src/components/             SpindleApp (state root), SignIn, PrepareTab, StudyView, JournalTab, ProfileTab
supabase/migrations/        schema + RLS (run in Supabase SQL editor)
```

## Data model

- `profiles` — 1:1 with `auth.users`: first_name, calling, family_context, study_focus, spiritual_season (all optional, length-checked in SQL and in code). Missing row = onboarding not done → `ProfileTab` renders in onboarding mode ("Skip for now" writes an empty row).
- `journal_entries` — user_id, reference, volume, anchor, content (full study JSON), created_at. Indexed `(user_id, created_at desc)`.

## Study content contract

Eleven sections, exact order (PRD §5 + conference addition): placement, background, people[2], principles[2], patterns[2], christ, conference[2] (general-conference teachings — speaker/talk/session/point, with a no-fabrication guardrail in the prompt), crossRefs[2], reflection[3], invitation, anchor. `StudySchema` in `src/lib/study.ts` is the single contract between API and UI — change it in one place only. Studies always generate ALL sections; `profiles.hidden_sections` (Settings tab) controls rendering only, so journals stay complete. Old journal entries may lack newer sections — render with guards (`c.conference ?? []`).

## Design system (PRD §7)

Tokens in `globals.css` `:root` (blue `#2b4bd7` / deep `#1d2f8f` / amber `#e0a428` on `#f6f7f9`). Sora for display, Inter for body (via `next/font`, so fonts work offline). Signature pieces: segmented tabs, chapter tiles (amber ring when selected), gradient reference plate, near-black anchor block, blue-soft Christ panel, sticky selection bar with safe-area padding. Accessibility: `aria-pressed` on all toggles, visible `:focus-visible`, `prefers-reduced-motion` honored, footer verse 2 Nephi 25:26 on every view. Print styles hide `.no-print` and avoid breaking inside sections.

## Rate limiting

Per-user 15 studies/hour, enforced in `/api/study` by counting the user's `journal_entries` in the last hour (RLS-scoped, stateless). Client-side soft warning above 10 selected chapters; hard cap 20 in `validateSelection`.

## Env vars

`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `ANTHROPIC_API_KEY` (server only — dedicated Spindle key, not Dossier's), `ANTHROPIC_MODEL` (optional). See `.env.example`; operator setup in `SETUP.md`.

## iOS app (Plug and Play)

Spindle is a consumer of `davidcblake/plug-and-play` (Capacitor remote mode — the shell loads the deployed Vercel URL, so every deploy IS the app update). Thin wrapper workflow at `.github/workflows/ios-build.yml`; bundle id `com.wpv.spindle`. **Repo must stay public** or macOS Actions minutes bill at 10×. Same install flow as Dossier: Actions → "iOS build (Capacitor)" → download `ios-project` artifact → open in Xcode → run on device (free signing expires after 7 days).

## Things NOT to do

- No AI calls from the client, ever
- No storing raw model errors with key material in responses
- No update policy on journal_entries; no widening RLS
- No localStorage for auth state (Supabase cookies handle it)
- Don't cache `/api/*` or Supabase responses in the service worker
- Don't add doctrinal content features without the faith-building guardrail in the prompt
